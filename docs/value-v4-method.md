# 价值模块 v4：可执行技能图输入、监督与论文论证边界

日期：2026-09-16。本文对应当前 v4 实现和已冻结的[实验协议](value-v4-protocol.md)；实际测量见[最终实验报告](../VALUE_V4_REPORT.md)。研究对象是**从原始滑台场景的真实机器人仿真执行检查点出发，对完整装配后续计划估计成功概率**。这里的“真实执行检查点”指通过 MuJoCo 中的机器人控制逐步装配得到状态；它不是实物机器人实验。

方法的核心接口可以概括为：执行前观测、任务目标和候选 PlanIR，经同一个技能接口注册表编译为可执行图；价值模型输出一个计划级 logit；Top-K 导出原 PlanIR 和完整图，交给物理验证器执行。需要检验的是这种统一表示是否减少特征维护工作，并在合理推理成本下保留有用候选。图网络是否优于序列或简单 MLP，需要独立实验回答。

## 1. 与已有方法的准确关系

| 工作 | 原工作已经解决的问题 | 本仓库应如何界定差别 |
|---|---|---|
| PIGINet，RSS 2023 | 对任务计划、图像、目标和初始状态做类型化融合，用 Transformer 预测计划能否被运动规划器细化。初始状态包含物体位姿、门关节角等连续值；用于评分的 task plan 去除了待求解的连续动作参数。 | 不能写“PIGINet 没有物理参数”或“首次整计划评分”。当前改动是将实际控制调用、已有运动航点和待求解参数来源共同放入与执行器绑定的表示，并学习闭环装配执行结果。参见原文 III、IV 节及 Table II。[论文](https://roboticsproceedings.org/rss19/p061.pdf) |
| SayCan，CoRL 2022 | 用技能价值函数描述当前状态下的技能可供性，并与语言模型提供的技能相关性结合，执行长时程语言指令。技能成功价值和语言规划的结合已有先例。 | 本轮模型直接对候选的完整后续计划评分；本轮候选来自确定的技能模板与合法参数组合，尚未测量 LLM 生成的多样性和端到端贡献。[论文](https://arxiv.org/abs/2204.01691) |
| STAP，ICRA 2023 | 协调独立学习的技能之间的几何依赖，利用下游 Q 值乘积估计技能序列成功，并优化动作参数；包含仿真及机器人实验。 | 跨技能依赖和长时程成功预测已有工作。这里采用整段实际执行的二元监督，输出单个计划 logit；当前没有训练逐技能 Q 函数再求乘积。[作者论文](https://www.chrisagia.com/papers/STAP-ICRA-2023.pdf) |
| Text2Motion，2023 | 结合 LLM、技能库、技能 Q 函数和几何可行性规划，通过整序列生成与搜索处理长时程依赖，并检查预测状态是否满足语言对应的目标。 | “LLM→候选计划→可行性筛选”和目标检查都不能单独作为新颖点。这里应检验可执行接口统一、物化/待求解参数共存及重型物理验证前的快速筛选。[论文](https://arxiv.org/abs/2303.12153)、[作者项目](https://sites.google.com/stanford.edu/text2motion) |

## 2. 一个外部输入，明确保留已知与未知

使用者提供的评分输入是一个可执行图列表。每张图内部包含一份 PlanIR；不要求使用者再填写“抓取难度、释放难度、路径风险”等人工评分向量。

| 输入块 | 当前来源 | 进入模型的信息 |
|---|---|---|
| 初始机器人状态 | 仿真观测 | 关节位置、手指位置、末端位置 |
| 场景对象 | 原滑台、导轨、零件及供料夹具 | 初始位姿、几何形状与局部几何变换；名义质量、惯量和摩擦参数 |
| 任务目标 | 装配任务定义 | 对象绑定、目标位置、位置与倾斜容差、验收谓词 |
| 每次技能调用 | 实际执行函数签名、默认值及端口声明 | 技能、实现分支、参数值、类型、单位、坐标系、known/deferred/unknown 状态 |
| 已物化初始路径 | 当前检查点的 IK/必要碰撞检查 | 关节起点、每个关节航点、末端目标、旋转矩阵 |
| 待求解参数 | PlanIR 的生产者引用 | 名义目标、前序调用及其输出来源；不包含未来实测状态 |
| 调用与状态依赖 | 技能契约和读写声明 | 执行相邻、数据来源、物体状态、持物关系、场景、机器人、观测及反向关系 |

对象名称用于找到对应的观测对象，网络读取绑定对象的属性。候选编号、路径编号、执行结果、未来位姿、错误日志、几何代理分数与检查点日志不作为模型特征。初始物理参数是评分时已有的名义模型数据；每次 rollout 的摩擦、驱动增益扰动属于未知执行条件，不提前泄露给评分器。

端口类型、单位、状态读写和目标容差仍需要正确的工程声明。接口统一降低的是另写一套产品专用价值特征的负担；它不会自动发现全部物理状态，也没有证明现有观测就是最优或充分的统计表示。当前使用仿真特权位姿和几何，没有视觉编码器。

### 已规划路径与反馈路径

`materialize_initial_path(session, plan, route["path"])` 将当前检查点的一条自由运动路径放入 `prefix.initial_artifacts`，移除对应的首次在线规划调用，并更新执行边界。相邻的移动调用消费这份原始路径；后续在线规划产生新路径时覆盖同名 artifact。

初始路径必须绑定当前起始状态、当前抓取轮次和候选身份。执行时恢复其数值数组，并验证自由运动和抓取轮次仍一致。评分图与执行 PlanIR 的内容哈希、技能接口和编码表示签名共同约束数据来源。单元测试还直接记录 MuJoCo 伺服接收的关节命令，检查它们与保存路径逐点一致。

抓持以后，物体相对于夹爪的变换由反馈确定，因此后续搬运路径保持 `deferred`。这一部分的评分是**对条件式执行程序的成功估计**；当前没有声称在执行前已知每一段接触轨迹。所有已存储航点都进入图编码，长向量分块，不做 24 点抽样；但这些航点仍是运动规划器输出的离散路径，并非带时间戳的完整高频速度、加速度或扭矩轨迹。

图边由保守的技能读写声明构建。它们描述前序动作可能如何影响后续动作，不是经物理干预识别的因果边，也不能证明路径无碰撞或授权跳过中间调用。

## 3. 直接学习完整执行成功，无人工加权分数标签

设配置为 $c$，检查点为 $h$，候选计划为 $p$，执行扰动为 $\xi_r$。输入图记为 $G_{c,h,p}$。完整程序执行后，得到：

\[
y_{c,h,p,r}=\mathbf{1}\{\text{程序正常完成且独立任务验收通过}\}.
\]

当前独立验收检查目标位置、倾斜、零件释放、手指接触及声明的末端净空；程序内部还保留各技能自身的执行与验收条件。所有目标都要满足，成功不由候选自己宣称。默认位置容差为 1.5 mm、倾斜容差为 3°；末端净空默认值为 0，不能把这个默认谓词解释成独立验证了 10 cm 撤退距离。还没有测量装配后的全行程功能、长期稳定性、磨损或真实制造质量。

模型输出 $z_\theta(G)$，名义概率为 $p_\theta(G)=\sigma(z_\theta(G))$。同一候选有 $R$ 次独立扰动重复，经验成功率为 $\bar y=R^{-1}\sum_r y_r$。训练目标使用二元交叉熵：

\[
\ell(G,\bar y)=-\bar y\log p_\theta(G)
 -(1-\bar y)\log(1-p_\theta(G)).
\]

在同一候选的重复数固定时，对经验率做这一步监督，等价于对其逐次 Bernoulli 结果的负对数似然取平均。实现按配置、检查点和候选分层平均损失，每个配置完成梯度累积后更新一次。这里没有把“距离、耗时、接触力、碰撞惩罚”等指标人为加权成分数后再拟合，也没有逐技能成功率独立相乘的假设。

人工设计仍包括任务验收、控制限值、合法技能先后关系、候选采样范围和扰动分布。这些定义实验任务及控制器；它们应在看测试结果前固定。无人工加权评分不等于没有任务假设，也不是此前方法都依赖复杂人工奖励的证据。

物理失败保留为负例，全成功和全失败候选池都保留。计算机墙钟超时视为删失，保存记录但不标成物理失败，也不生成可供训练的完成组。准备检查点失败必须单独报告，不能替换成瞬移到位的场景。

## 4. 编码、紧凑化与公平对照

通用端口编码使用字段身份、类型、单位、坐标系、状态、类别和数值通道。当前数值通道包含固定的多尺度 `tanh` 变换；词身份使用固定哈希空间。这些也是表示选择，需要消融检查，不能称为无损或最优。它们与后续由训练输入拟合的均值、标准差共同使用。

| 模型 | 共享输入及区别 | 可以检验的问题 |
|---|---|---|
| 未裁剪端口集合 MLP | 从训练图建立端口词表，将同类端口做通用汇总，64→32→1 | 接口派生输入能否支持简单评分器 |
| 紧凑端口集合 MLP | 使用相同词表与汇总，仅依据训练输入删除近似常量列、逐位相同列；保存列索引 | 有限训练分布内的存储、参数量及预测成本是否可压缩 |
| 同输入序列模型 | 调用内注意力汇聚，再用宽度 64、2 层、4 头模型处理调用序列 | 完整顺序信息能否改善评分 |
| 状态依赖图模型 | 与序列模型相同，只增加关系注意力偏置 | 显式依赖是否提供额外收益 |

紧凑化的词表、列索引和归一化统计只由训练输入拟合；验证或测试数据不能决定保留哪些列。新输入使用原列索引，未见端口不自动获得已训练参数。训练中两列恰好相等不代表它们在新任务中永远等价；集合汇总也丢失了精确调用顺序。因此紧凑模型只能作为资源与效果的对照，不能凭压缩率宣称已找到任务最小充分表示。

图和序列模型读取相同类型端口、顺序位置及初始上下文，使用相同网络宽度、深度、训练划分和随机种子。单纯在推理时删边或乱边只适合作为诊断；图结构增益应以单独训练的同输入序列模型为主要对照。旧版 87 维摘要或旧字段 Transformer 若未接入新增路径/物理信息，需要明确标注输入差异，不能充当这一组严格同输入对照。

验证集用于选择最低 Brier 的训练轮次，再拟合正尺度的仿射 logit 校准。校准不反转计划顺序；若验证集只观察到一个结果类别，保留恒等校准并报告原因。部署与离线排序使用 logits，概率用于 Brier 和 log loss，避免 sigmoid 饱和造成额外并列。验证集同时用于模型选择和校准的结论需要另一个独立测试集检查。

## 5. 本轮滑台实验具体覆盖什么

本轮使用原始滑台装配场景。机器人先装配滑块和端挡，得到检查点 2；或者继续按现有生产配方装好左销，得到检查点 3。前者候选完成左右销和手柄，后者完成右销和手柄。完整 PlanIR 分别为 58 或 40 次调用；这包含准备、反馈和检查调用，不能写成 58 或 40 种不同的原子技能。本轮候选由程序模板和合法参数组合生成，用于隔离价值模块的效果；目前没有通过这组实验验证 LLM 自然语言任务理解或候选生成质量。

左右销安装顺序可在装配约束允许时交换，手柄保持最后安装。每个待装配零件具有独立抓取选择；路径、夹持力和下降速度变化实际进入控制。候选经固定随机顺序枚举和可执行内容去重，不靠无意义编号或低于控制分辨率的扰动扩充数量。首次路径只做必要 IK/碰撞检查，执行中的接触和闭环结果仍未知。训练分布是**经过这些生成规则与必要检查后的候选分布**，不是任意机器人程序的分布。

冻结协议采用 12 个训练、4 个验证、8 个测试配置，每组 N=8、R=2。初始供料位置变化，仿真执行额外施加摩擦和驱动增益扰动；所有候选在同一重复中使用配对扰动。每个配置本轮只有一个检查点，长度类型都在训练和测试中出现，因此不能据此宣称未见长度或跨任务泛化。准确种子、模型和部署规则以协议及运行产物为准。

应同时报告 near-best Hit@1/2/4、可行命中、Top-K 平均经验质量、regret、Brier、log loss、随机选择解析期望和配置级置信区间。R=2 时经验质量只可能为 0、0.5、1，经验最优会受重复噪声影响；Hit@4 仅表示选出的 4 个中至少有一个达到定义的近优质量。全失败池只从 near-best Hit 的分母排除，仍参与可行命中、质量和概率误差。

当前训练轮次选择中的 `brier` 是预测概率到候选经验率的平方误差。逐次二元结果的平均 Brier 还需加上 $\bar y(1-\bar y)$，分析脚本将后者另记为 `bernoulli_brier`。同一候选池上这个附加项不改变模型优劣顺序，但两种绝对数值不能混用。配置级 bootstrap 反映已观察配置的差异，没有补足 R=2 对单个候选真实成功概率的估计误差。

价值模型耗时需要分别测量图构造、完整性检查、编码、推理及导出。若要论证整体系统加速，还需要实际运行 Top-K 验证、按相同准则选计划、再做独立执行，并与相同硬件及验证预算的基线比较。不能用 N/K 直接当作加速比，也不能用标注 rollout 成功率替代独立部署成功率。

## 6. 面向 RAL 的可检验假设

| 假设 | 所需证据 | 不能由当前实现直接推出的结论 |
|---|---|---|
| H1：统一接口能降低价值输入与执行参数不一致的风险 | 路径/参数变更、错误绑定、接口升级及真实执行重用测试；更换场景时输入维护工作量记录 | 编码自动完整、没有人工声明、形式化证明所有控制器语义 |
| H2：轨迹和控制端口对候选排序有帮助 | 相同数据和预算下，训练“完整输入”与“移除轨迹/控制输入”模型；在新配置做配对比较 | 输入更多参数必然更好、目前参数集合最优 |
| H3：状态依赖图在多部件装配中有增益 | 同输入图/序列多种子、未见依赖组合、配置级差值区间 | 仅凭图可视化或注意力图宣布优于序列、学到了因果关系 |
| H4：快速评分能改善有限孪生验证预算下的执行效果 | 同预算完整闭环成功率、时间分解、不同 N/K 与候选池难度 | 模块推理快就等于端到端快、数字孪生成功等于真机可靠 |

若紧凑 MLP 与图模型相当，应如实解释为当前数据尚不足以证明关系结构有价值；若都未超过随机或源顺序，也应保留结果并分析候选池难度、标签重复数和训练覆盖。小样本结果不能通过事后修改测试集或插入已知成功候选来修复。

## 7. 实物实验还需要覆盖的分布

下一步的主要工作是建立可信的部署分布，而不只是增加同一仿真配方的随机种子：

- 使用可获得的相机、机器人反馈和 CAD/标定信息；明确哪些位姿、摩擦或质量在真机评分前可知，以及相应估计误差。
- 覆盖供料定位误差、零件与孔位公差、抓取偏差、接触摩擦变化、夹具变化、工具与机器人重复定位误差。范围应来自实际测量或制造规格，并记录失败模式。
- 保留真实工作中会出现的候选分布：将 LLM 生成、技能图约束和必要几何检查分别留痕，统计候选数量、重复率、合法率和可执行覆盖，不只测手写模板。
- 按独立实体/批次、工装配置和采集时段组织划分；同一实物配置的多计划、多重复和多检查点保持同组。所需样本量由预期效应和不确定性要求决定，不能把大量相关 rollout 当成大量独立装配场景。
- 以独立测量确认装配位置、保持和功能验收，并统计重试、人工干预与实际验证耗时。若论文声称滑台完整装配，需要进一步覆盖前两部件与功能测试。
- 测量仿真到实物的评分校准和候选排序迁移；如允许用新任务数据重训，应分别报告从头训练、适配及零样本迁移，避免混写。

当前较稳妥的论文表述是：**提出并检验一种由可执行技能接口编译的计划级价值输入，在同一表示中保留已知运动参数与反馈待求解来源，并在接触装配继续任务中评估有限验证预算的候选筛选。**这是一组研究假设及可复现实现，不是已经证明达到 RAL 录用标准的结论。
