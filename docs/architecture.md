# 基础能力、候选实例与共享契约

状态：2026-09-08 已实现接口整理、多解构造和共享契约。原控制器、场景物理参数、行为克隆权重与演示视频保留。价值网络及完整任务 Top-k 孪生调度尚未实现。

## 1. 少量执行接口，保留已有控制器

`Session.call()` 是统一入口。`interfaces.py` 将参数模式解析到原来的处理函数，不合并其物理成功判据。

| 执行接口 | 模式 / 参数 | 原有检查 |
|---|---|---|
| `observe` | `scene` | 仿真位姿观测及噪声模型 |
| `move` | `joint_path`、`cartesian_path`、`approach`、`align`、`orient` | 规划数据、启动状态、位姿跟踪及对应抓持要求 |
| `move` | `lift`、`lower`、`retreat`，用 `height` 控制距离；`home` | 抬升必须持物且物体确实上升；下移保持抓持；退出和关节回位要求空夹爪 |
| `gripper` | `open`、`close`，`force` | 张开宽度 / 同一物体的双侧接触 |
| `guarded_move` | `descend`、`seat`、`retract` | 力阈值、保持抓持、压靠高度与接触、恢复计划 |
| `insert` | `axis`、`spiral`、`learned` | 对象/插入参数、几何适用性、失抓与力限制、目标误差 |
| `actuate` | `slide`，`target_x` | 导轨约束方向、力限与运动误差 |

例如，`s.call("move", mode="lift", part="cube", height=.10)` 和旧的 `s.call("lift", part="cube", height=.10)` 使用同一契约、同一控制函数。`home` 仍回到原来的关节目标，不替换成近似的笛卡尔目标。

保留 30 个组件名称用于兼容和独立演示，它们不是 30 个平级动作：

- **executable**：上述执行能力的实际处理函数。
- **generator**：位姿估计、抓法生成/选择、关节/直线路径、插入及恢复参数生成，不推进物理仿真。
- **checker**：夹持、装配位置、行程及间隙检查。
- **macro**：`pick_template`、`release_template` 展开为基础调用；装配顺序是更长的任务模板。

图导出包含 `kind`、`family`、前置条件、效果、输出绑定和未知义务。规则插入和学习插入是同一接口的不同控制模式；学习模式仍是行为克隆。

## 2. 同一个模板，保留多种参数实例

`build_pick_candidates()` 对每个抓取姿态构造三种高度的接近路径，分别求 IK、做离散碰撞检查，不会找到第一条可行路径就退出。已知碰撞只否定对应路径；有限 IK 预算失败的抓法和路径仍保留为 `unknown`。

每个 `Candidate` 明确携带：

- `grasp`：姿态、开度、观测位姿指纹与抓法 ID。
- `path`：实际关节序列、起点、末端目标、朝向和绑定；尚未求得时为 `None`。
- `control`：实际执行的策略及力参数；Pick 当前支持反馈闭爪，可传入多组正力阈值。
- `terminal`：任务给定的终态目标，没有后缀时默认为持物/抬升目标。
- `bindings`：对象、抓法、路线、控制和目标之间的关系，以及后续搬运的待求解请求。
- `status / unknown`：已做必要检查的结果和尚未验证的接触、连续扫掠、后缀约束。

装配 `pick()` 已使用这条构造链，不再按零件名称选择抓法索引。`select_grasp(index=...)` 保留为可复现的显式兼容入口，默认按几何代价选择，也支持 `candidate_id`。

**采用逐阶段展开，不伪造一整条已经验证的轨迹。** 抓取前保留多条具体接近路径；真正闭爪成功后，再用测得的手—物关系生成多条持物搬运路线。每条搬运路线绑定原候选 ID、抓法 ID、抓持轮次及当前关节起点。跨抓法、跨释放/重新夹持轮次复用旧路径会被拒绝。

装配输出 `candidates.json` 保存所有抓取候选及所选前缀的搬运扩展，包括失败/未知路线。未选分支的搬运和接触后缀保持待求解，不宣称它们已通过数字孪生。

### 启动排序与一个实际反例

当前采用显式几何代价，**不是训练出的价值模块**。代价包含抓取运动量、路线高度和终态张爪空间的采样碰撞惩罚。

仅按当前抓取代价排序时，装配在左销插入后的张爪步骤失败：可张开宽度约 64 mm，未达到原有 75 mm 成功阈值。加入任务终态附近的张爪空间代理检查后，种子 0 的完整装配通过；没有放宽阈值或改变控制器。

张爪检查只在独立 MuJoCo 数据中投影物体目标和名义抓取偏移，采样 9 个开度。它依赖假设的后续状态，因而只提供排序惩罚，不以此删除候选。它不能替代接触仿真，更不是价值学习的实验证明。

## 3. 执行和图谱读取同一契约

`library.py` 的 `Spec` 声明 `requires / effects / produces / output_bindings / obligations`；`contracts.py` 统一解释。

- 执行器运动前检查资源、对象和规划绑定，并读真实双侧接触。成功后才提交声明式状态效果；生成器输出也检查声明的类型和绑定。
- 图谱按“每一步执行成功”的条件传播相同效果、数据和夹爪占用；场景对象与几何能力可由外部提供，支持独立方块场景。
- 检测→位姿、抓法→接近、闭爪→持物动作等关系由数据/效果契约生成。旧手写衔接列表已删除。

一条连线只表示前一步能提供某些条件，不表示已满足下一步全部条件。`validate_skeleton()` 检查的是**整条绑定后的调用链**。

| 返回内容 | 含义 | 后续处理 |
|---|---|---|
| `status="conflict"` | 已发现对象、类型、占用或绑定矛盾 | 拒绝这一具体组合 |
| `necessary_checks_passed=true` | 通过本次所做的必要检查 | 可以保留，不等于物理成功 |
| `status="unknown"` 与 `unknown` 列表 | 仍需生成参数、测接触或验证连续约束 | 保留给求解/孪生验证 |
| `status="necessary_pass"` | 当前声明的检查没有遗留未知项 | 仍只覆盖声明和检查的范围 |

兼容字段 `valid` 表示“未发现冲突”。生成器尚未运行的输出标记为 deferred；图谱继续传播类型，并保留具体身份未知的义务。真实执行不允许拿 deferred 数据直接运动。候选路线的 `status` 只描述该路线已做的检查，额外的后缀义务仍在 `unknown` 中。

## 4. 复现与下一步

```bash
python -m pytest simbench/tests -q
python -m simbench.assembly.graph --out results/skill_graph.json
python -m simbench.assembly.candidate_demo --out results/candidate_demo
python -m simbench.assembly.task --out results/tabletop/assembly
```

`candidate_demo` 从同一完整快照执行两种方块抓法。`candidates.json` 只存仿真前候选输入；`outcomes.json` 单独保存回放结果，并明确标注只验证抓取前缀。
