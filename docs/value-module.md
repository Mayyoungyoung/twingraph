# 面向后续任务的价值模块

状态：设计方案，尚未在当前滑台上训练或接入。旧 Task C 专用原型已移除，不能作为当前方法的实现或成绩。

## 价值定义

先要求当前任务成功，再比较成功终态对后续任务的影响。不能把相同的 success 判据再训练一遍。

- 已知后缀：`V(s, g_next)` 衡量后续成功率、时间和恢复代价。
- 未知后续任务：在明确定义的任务分布下计算期望，不混用两种设置的成绩。
- 仿真前排序：用 `Q(s0, candidate_plan, g_next)`，或廉价终态预测器加 V。输入不得含完整仿真后才知道的真实终态与成功标签。

先使用成功概率、时间、换抓/恢复次数和不确定性的多头模型，再按实验协议组合排序。当前任务失败不能被较好的未来分数掩盖。

## 数据采集

在同一初态和骨架下改变抓取位姿、路径、插入策略、释放/退回姿态；也比较通过条件检查的不同骨架。每个候选从同一完整快照开始，恢复物理状态、控制器、随机数与相关模型参数。

当前任务验收通过后才开展后续任务试验。记录场景/对象/布局/种子分组、初态观测、对象和参数绑定、检查结果与未知约束、当前成功、终态、后续成功、耗时、恢复次数、失败原因及版本。

同组候选使用配对扰动与后续任务样本，采集失败和难区分例，不仅保存漂亮的成功演示。

## 训练

初版使用结构化特征与小型 MLP：对象相对位姿、抓持关系、剩余空间、关节余量、候选参数和后续任务描述。数据足够后再考虑对象图编码器。

联合后续成功监督、代价回归与组内排序。优先学习明显差异，不强迫噪声接近的候选形成可靠全排序。

按场景、对象、布局和任务组划分训练/验证/测试。同一初态的兄弟候选不能随机拆分，真实 rollout 终态不能泄漏到仿真前输入。

## Top-k 评估

评估最优/近优候选保留率、Top-k 是否包含可行解、最终后续表现、仿真调用次数和总耗时。平分候选使用明确近优容差，避免任意 tie-break 改变 Recall@k。

对照包括随机 Top-k、局部成功/代价排序、几何启发式、全候选仿真和学习排序。保持预算一致，计入候选生成与推理成本。

Top-k 全部失败时在预算内扩展或重新采样，不能直接宣称任务不可行。可对高不确定候选保留探索配额。

## 当前场景切入点

比较抓持姿态对插入/撤回的影响、滑块结束位置对手柄安装及后续抓取的影响、放置姿态对下一操作的影响。先验证差异可重复，再大规模采集。

硬性违反已知启动条件的候选由图谱处理；都能继续执行但时间、换抓或鲁棒性不同的候选由价值模块排序。
