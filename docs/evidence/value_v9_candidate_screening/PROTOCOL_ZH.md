# V9 冻结任务的候选筛选实验协议

任务版本固定为 `functional_assembly_v9_funnel_r1`；几何、工作区、销孔验收、
RGB-D 感知接口及参考执行器沿用提交 `29b5212` 的实现。本轮只增加候选池、
独立 Session 采集和排序比较。V9 参考策略的隔离左销失败继续保留，未修改标签。

## 候选来源与执行语义

本轮 12 个候选由 `simbench/value/v9_candidates.py` 的明确脚本生成，
**不是大模型规划结果**。统一 `PlanIR`/`run_full_task_v7` 接口仍可供后续
大模型候选使用。仓库中未找到实际调用外部大模型的在线候选生成器；旧报告中
的离线 LLM 代理不能计作本轮在线生成。

候选 0 是 V9 参考策略。其余候选改动：合法插销顺序、两销插入速度、两销抓力、
两销抓取高度、转移间隙、挡块接触速度、擦拭路径方向或擦拭时长。五件物体、
任务行程下限和验收完全相同；没有注入违反前置关系的计划。静态原子技能调用
序列审计为 12/12 唯一。实际运行痕迹还需核对 `propose_grasps`、
`plan_transfer`、`close_gripper`、`plan_insertion`、擦拭轨迹和执行顺序，
只把真实控制命令不同计为可执行多样性。

## 采集与划分

先在新布局 seed 1300、1301 各试四个候选的名义条件，保留全部失败；之后
预定连续新布局 seed 1302–1313，每布局 12 候选 × 3 配对条件，共 432 次
完整任务执行。条件为名义 `(friction=1,gain=1)`、轻低
`(.95,.995)`、轻高 `(1.05,1.005)`，仅缩放 MuJoCo 物理模型数组，
每次建立全新 Session。原始场景 XML 的物理几何元素哈希用于布局去重；
采集时保存运行前 RGB-D 检测结果、候选来源、执行参数、完整原子技能日志、
失败原因、物理模型参数哈希及计时。运行前检测可能包含静态 CAD 辅助；
执行后历史观测、CAD 关系和已验证行程终点的目标推导继续带来源标记，
不得写成新视觉实测。

训练/验证以布局为组：前八个开发 seed 训练，后四个验证；三条件、十二候选
在同一布局组内，不按候选行随机拆分。独立目标布局预定 seed 1400、1401、1402，
每布局沿用同样三种配对条件，在目标执行前冻结排序，不用目标结果更新排序。

## 比较口径

比较固定参考、随机无放回顺序、预定简单规则、轻量数值模型、现有 V6 价值
网络的数值架构，以及 Full-12。K 为 1、2、4、8、12；每种方法按自身排序
依次孪生验证，首次完整通过即停止。随机基线每个布局条件重复 256 个预定
随机顺序。固定参考只有一个方案，不计完整候选池生成或网络推理开销。
离线回放使用同一完整结果矩阵与实测验证时长；另外在独立目标布局实际执行
排序、独立 Session 验证和早停，报告实测端到端时间。没有真机结论。
