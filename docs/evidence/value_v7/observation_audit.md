# v7 观测审计

## 真实观测边界

当前 v7 是“仿真真值经过统一传感器模型”的模拟感知代理，不是真实 RGB-D 检测器。`observation.py` 在决策边界读取隐藏 MuJoCo 状态一次，加入位置和偏航误差，冻结为 `twingraph.observation.v7`；候选生成 scratch session 和四种视觉消融共享这一份观测。target 物理扰动、污迹剩余量和未来执行结果不进入该对象。

机器人关节、夹爪和末端状态属于可观测本体状态；零件 CAD/几何属于已知设计信息；真实零件初始位姿是隐藏状态，只通过模拟传感器代理进入估计。当前 RGB-D 是可用相机的仿真渲染，不声称完成真实位姿检测。

## 已发现并修复

- 旧 `Session.estimate_pose()` 直接读取真实四元数；v7 使用冻结带偏航噪声四元数。
- 旧候选路径部分读取 `ctx.obj_pos()`；v7 scratch 复制决策观测，初始 carriage transfer 使用观测位置。
- v6/旧 wiping 只有二维覆盖遥测；v7 增加污迹状态、pad-only 接触和独立移开验收。
- 旧 stroke 只看一维范围；v7 检查双向、横向偏移、峰值力。
- 装配后的 stroke 曾错误复用决策边界冻结的供应区把手观测；新增
  `observe_execution_pose` 执行期传感器代理，明确区分冻结决策观测和执行期
  物体跟踪反馈，避免末端去抓旧位置。

## 仍保留的简化

- 传感器是模拟噪声代理，不含真实 RGB-D 深度缺失、遮挡分割或检测网络误差。
- 清洁状态是接触条件驱动的可见污迹模型，不是精确材料去除或颗粒动力学。
- 任务仍使用已知 CAD 和固定工装设计值；独立验收器可访问仿真真值，但决策器不应访问。
- 执行期跟踪目前仍是仿真位姿反馈代理（不是 RGB-D 目标跟踪器）；它只用于把末端
  重新对准已经安装的把手，不进入候选评分、训练标签或 target 扰动。
