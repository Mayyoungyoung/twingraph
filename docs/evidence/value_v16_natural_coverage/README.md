# TwinGraph V16：自然候选覆盖与完整执行可靠性

## 结论

本轮在 `research/value-v15-full-system` 的提交
`6fcf4e66d7572242b1d089fc47289370465a2b77` 上建立 V16，并在 901 的冻结运行时中完成了
3 个预先声明开发布局、每布局 16 条自然候选的完整物理执行。48 条候选全部有有效物理标签，
但没有一条完成冻结 TaskSpec 的全部功能验收：首批自然覆盖率为 **0/3**，三个候选池均为全负池。

因此，V16 的正式结论是：新增抓取中心自由度和擦拭接触卸载修复让执行越过了 V15 的一部分公共前缀，
但尚未把“自然候选中存在完整成功计划”做扎实。当前主要阻断已转移到端挡座入、抓取接近和插销接合。
现有 V15 价值模型在这批数据上无法检验是否筛掉成功方案，也没有可用于同场景正负排序的新训练对，
所以本轮没有为了得到好看的排序数字而重训或修改标签。

机器可读汇总见 [RESULTS.json](RESULTS.json)，冻结运行时清单见
[FREEZE_MANIFEST.json](FREEZE_MANIFEST.json)。

## 通用规划与控制修改

### 1. 对象坐标系抓取中心成为原子技能的通用输入

`center_offset` 现在是带单位和坐标系的原子技能端口。CAD 可声明一个或多个对象坐标系内的合法抓取中心；
候选目录对每个中心使用同一套抓取面、夹爪宽度、源场景、目标场景和接收体净空检查，然后把选中的偏移
一直传到 PlanIR、语义重建、技能图验证和实际 `estimate_grasp`。对象旋转时，偏移随对象姿态变换，
不会把世界坐标偏移误当成物体坐标偏移。

本任务的 CAD 配置为 carriage 声明中心及 ±12 mm 的 x/y 偏移，为 end_stop 声明中心及 ±8 mm 的 x/y 偏移，
handle 保留中心抓取。它们是零件抓取区域配置，不进入价值网络的任务专用特征，也不包含 seed、候选编号或成功标签。
相同端口和目录逻辑可由其他装配任务的 CAD 直接复用。

### 2. 抓取接近和承载抬升的有界纠偏

当长距离笛卡尔下降刚好停在 1 mm 契约外时，执行器从实际到达状态重新求解，并只做一次较慢的有界纠偏。
承载抬升增加显式速度契约；若第一次到达失败但双侧夹持仍存在，则朝同一已检查绝对目标做一次慢速重试。
这些路径不传送物体、不重建抓持，也不改变成功验收。

### 3. 擦拭工具从接触态物理卸载

V15 的单步自由空间抬升会在泡棉仍压缩时拉扯工具，造成共同前缀丢抓。V16 在擦拭技能内部以 20 μm 步长
执行最多 300 步的力引导回撤，要求表面力低于 0.05 N、工具实际抬起超过 1 mm 且双侧夹持持续存在，
然后才允许 0.01 m/s 的 0.10 m 自由空间抬升。接触工具的夹持力从重力搬运用的 8 N 调整为 15 N。
这是对接触工具负载阶段的统一控制，不按布局选择。

开发探针的 r1/r2 直接抬升只让工具移动约 4.7 mm；r3 更小分段抬升反而丢抓；r4/r5 的力引导卸载能达到
零接触力和约 1.01 mm 物体抬升，但后续承载仍会丢抓；r6 加上接触阶段夹持力和慢速自由抬升后通过清洁前缀，
并进入 end_stop、pin 等后续阶段。正式矩阵只使用冻结的 r6，开发探针没有混入覆盖率统计。

### 4. 保守源零件接触保持为“未知”，交给孪生验证

完整夹爪壳体对被抓零件的预期接触会被保守碰撞检查判成穿透。V16 仅在环境/接收体路径无穿透、
抓取面合法时，将这类行保留为明确的 `unknown` 并送数字孪生；它们从不被重标为几何通过。
已知环境碰撞和非法抓取面仍然硬拒绝，没有全局关闭碰撞检查。

## 为什么不是按布局定制答案

- 代码中没有对 `1950/1951/1952`、layout ID 或 `grounded_*` 的运行分支，也没有成功参数表。
- 新自由度来自 CAD 抓取区域和通用技能端口；几何目录在看到任何 rollout 标签前生成并冻结候选。
- 48 条候选全部从当前合法观测、TaskSpec、CAD、技能注册表和同一程序化规划流程产生；执行前保存 observation、
  proposal、PlanIR、输入图及其哈希。
- 任务目标、物理/碰撞几何、六个功能谓词、成功判据和失败记录均未为 V16 放宽。
- 开发时曾诊断更高端挡压力上限，但该 r7 探针仍失败，正式 r6 和提交代码保留原 4 N 上限；没有为了得到成功标签
  修改装配几何或验收阈值。

本轮保留了 V15 的 LLM/策略接口，但正式候选由
`codex_symbolic_plan_with_observed_geometry_catalog_v13` 程序化生成器产生，并非外部在线 API 自动调用。
Codex 在本轮承担交互式工程、诊断和实验编排角色；报告不把这一点冒充为在线 LLM rollout。

## 一条真实完整候选

`seed_1950/grounded_006` 是执行前自然生成并实际从 fresh scene 运行的完整程序。其顺序为：

```text
clean → carriage → end_stop → pin_left → pin_right → handle → functional verification
```

主要选择包括：

- carriage：对象相对 yaw 0、抓取高度 7 mm、中心偏移 `[-12, 0, 0]` mm、夹持力 8.769 N、
  搬运速度 8.58 mm/s、受保护下降上限 11.693 N、压入 1.728 N，并使用检查过的关节接近；
- end_stop：对象相对 yaw π/2、抓取高度 7 mm、中心抓取、22 mm 夹宽、2.209 mm/s、压入 1.464 N；
- 两枚插销：yaw π、抓取高度分别 4/7 mm、目标深度 43 mm、力上限 9.611 N、先抬升 80 mm；
- handle：yaw π/2、抓取高度 7 mm。

这条程序完成了清洁、carriage 和 end_stop 的前缀，并首次失败于 `learned_insert`：实际插销—孔接合没有进入
验收带。它是“认真规划但物理失败”的自然负例，不是手工制造的错误参数。完整物理记录见

## 端挡座入的当前边界

25/48 条候选的首次失败是 `press_seat`。CAD 中 end_stop 外廓为 24 × 86 mm，而定位结构形成的内间隙约为
22.46 × 84.46 mm，相当于每侧约 0.77 mm 的刚体干涉/卡扣配合。正式 r6 的 1.2–3.43 N 候选普遍停在座入带上方。

为区分“单纯压力预算太低”和“接触/控制模型仍不匹配”，开发后又做了一个不进入正式矩阵的 r7 诊断：
仅把上限扩到 8 N，一条候选实际到 6.485 N，最终高度约 30.2 mm，仍高于成功阈值 26.75 mm。
原始诊断见 [press_envelope_grounded014_result.json](raw/press_envelope_grounded014_result.json)。
这说明增加力预算会推进零件，但不足以完成冻结的刚体卡扣配合；下一步需要在不改 CAD 与验收的前提下，
修正端挡有限对齐/卸载/接触控制或更真实的柔顺材料模型。

这里的结论是“当前生成器与执行器未找到成功”，不是“该布局物理无解”。

## 历史成功与新鲜复跑差异

V15 记录中的 `grounded_016` 在新鲜运行时复跑失败。核查结果为：

- 声明的 trial 扰动完全相同：摩擦系数 `1.0652904951253181`、执行器增益 `1.0146867667890507`，
  trial SHA 均为 `9188e…`；
- V12 冻结物理源码与 V15 新鲜运行中的 physical-base 源码逐文件一致；V15 只新增了配置、价值模型与缓存文件；
- PlanIR 顺序、选择、调用和允许观测语义一致，但 fresh scene 的原始 start-state fingerprint 不同；
- 首个可见放大出现在 end_stop 闭爪：旧运行右侧接触力约 4.893 N，新运行约 4.640 N；之后左销规划目标
  相差约 46.6 μm，旧运行接合成功，新运行在 `learned_insert` 处径向误差 0.959 mm，超过 0.865 mm 允许值。

因此不能笼统归咎于“随机性”。现有证据指向：相同已声明扰动和同源物理代码下，未完整保存的初始 MuJoCo
状态不同，微小差异经刚性接触放大。历史记录只保存了原始状态哈希，没有保存可逐量比较的 qpos/qvel/ctrl 快照，
所以目前无法再定位到某个状态分量。这是明确的 provenance 缺口。V16 已冻结完整源码和矩阵输入；后续还应保存
可恢复的完整模拟器初态，而不只保存 fingerprint。

## V15 价值模块检查

V15 模型正常读取了 V16 的统一技能图输入，checkpoint 哈希如上。三个池的分数集中在约 0.458–0.464，
并产生了表中的 Top-4。由于 Full-N 都没有成功：

- 失败属于候选覆盖/执行问题，而不是“Full-N 有成功但 Top-4 筛掉”的排序问题；
- Full-N、原始 Top-4、确定性随机 Top-4 和 Value Top-4 的成功保留率都为 0；
- 无法判断价值模型有没有筛掉成功方案，因为池中根本没有成功方案；
- 这 48 条全负记录可用于适当的分类监督，但不能构造同布局正负排序对；
- 本轮不重训原结构。应在通用执行修复后收集到足够自然正例/混合池，再冻结池、按布局切分并复核 Top-4。

`center_offset` 作为已有原子技能参数经 PlanIR/技能图自动进入通用输入路径，没有为滑台另写价值输入维度。
这满足“价值模块输入与原子技能图整体统一”的约束。

## 测试与复现

本地针对性回归为 33 passed。901 上包含几何/规划路径的针对性回归为 45 passed。
完整 EGL 测试运行结果为 562 passed、3 failed、1 skipped；三项失败均因隔离运行时初始未复制已有 evidence fixture，

正式实验入口：

```bash
bash scripts/run_v16_natural_coverage.sh
```

脚本固定 r6 运行目录、环境、冻结清单、3 个布局、16 条/布局和 Top-4。若在其他机器复现，显式覆盖
`ROOT`、`VENV`、`CHECKPOINT` 即可；改变这些路径不会改变协议参数。汇总器不会给未执行候选补物理标签，
并把软件错误、资源截断与物理失败分开。

## 下一步的严格门槛

下一轮首先应在同一冻结 TaskSpec 上修复 end_stop 的真实座入控制，并同时保存完整可恢复初态。只有阶段 A
通过同一通用流程产生新鲜完整成功，才扩到阶段 B；自然混合池足够后才重训 V15 原结构并在独立布局测试。
在此之前，V16 不能声称已经完成“有好方案可选”，也不能声称价值 Top-4 已节省数字孪生验证时间。
