# V20：以完整流程最终成功为价值标签

## 目标与当前边界

价值模块按**一条完整计划从随机初始布局执行后，清洁、装配、双向行程、挡块捕获、最终就位、释放退回六项验收是否全部通过**学习排序分数。当前使用类平衡与成对排序损失，输出分数不应解释为经过校准的成功概率。任何挡板、插销、把手或清洁局部正例都不能代替完整任务标签。阶段审计只用于找出候选覆盖和控制器瓶颈。

历史 V15 完整任务矩阵中有少量成功记录，但当前严格运行时 V16 的三个自然候选池全部为全负池（48 条完整候选，0 成功）；详见 `docs/evidence/value_v15_full_system/REPORT_ZH.md` 和 `docs/evidence/value_v16_natural_coverage/README.md`。这些不同运行时的数据不能混合训练或用于新鲜成功率声明。V19 对各局部阶段做了自然覆盖诊断，但它不构成整任务正例。

## V20 数据门槛

`scripts/audit_full_task_pools_v20.py` 逐布局从 `request.json` 读取生成前冻结的候选池，逐条核对完整 `rollout` 的 `result.json` 与 `input_graph.json`。记录必须是 `complete_functional_task`、`full_task_label=true`、有六项最终验收字段、`full_success` 与执行成功一致、图/计划/运行时哈希一致，并且有效且未超时。缺失或无效的试次将所在池标成 `incomplete`；全负、全正池如实保留。

`scripts/train_value_v20_full_flow.py` 只接受同一冻结运行时、固定候选数且每个随机布局自然同时包含整任务成功和失败的池。布局在读取标签前按 seed 模 5 固定分为训练、验证、测试。任何池不混合或任何折缺失时，它输出 `coverage_audit.json` 后拒绝训练，绝不靠复制、改标签或按结果挑选候选制造正负样本。

输入来自同一执行前图：V15 通用装配原子节点，加上清洁和最终功能行程两个反馈控制器接口节点；两者的擦拭和行程参数必须与完整任务可执行 PlanIR 一致。当前清洁与行程控制器的内部自适应调用尚未逐个展开为 PlanIR 原子节点，因此该表示是**完整流程接口图**，并非已完成的全流程原子展开。V20 在对外结论中保留这一限制。

测试比较对每个冻结池复用相同的完整任务物理结果：全候选数字孪生验证；标签盲的均匀随机 Top-K 再验证；价值 Top-K 再验证。统计整任务成功率、孪生调用数，随机方法使用精确组合期望。时间先按逐候选实测墙钟求和，并单独记录图编码及推理；如果候选标签是并行采集，这个和只能作配对代理估算，不能当成在线决策耗时。正式在线耗时需使用 `scripts/run_v12_system.py` 在未见布局上串行精验复跑。共同的生成耗时和部署耗时单独报告。

LLM 候选生成分三步：`scripts/prepare_v20_llm_composed_pool.py --emit-prompt` 从未执行的冻结基础候选请求导出任务观测、真实通用技能图及合法求解端口；在具有 Codex CLI 登录的主机运行 `scripts/run_v20_llm_cli.py` 保存模型原始输出、版本及耗时；将输出送回 901 后，用 `prepare_v20_llm_composed_pool.py --response` 逐角色绑定成完整可执行计划、验证 PlanIR/价值图并在执行前冻结每条图哈希。随后 `scripts/collect_v12_parallel.py` 才允许执行该池。正式新场景必须在读取任何该场景 rollout 标签前冻结模型响应和候选池。上面的 seed 1950 为开发试验，不作为未见测试布局。

为扩大自然覆盖，`scripts/prepare_v20_expanded_natural_pool.py` 在同一场景将固定候选数从 48 扩为 96：先证明前 48 条按名称、全部参数和图哈希不变，再冻结新增 48 条；旧 48 条试次在完成后**无条件全量**复用，失败和无效记录也不筛掉。扩池规则一致地应用于 1950–1954 五个布局，仍需所有布局的最终正负混合审计通过才能训练。这个开发矩阵已读过 1950 结果，因此正式未见测试需要另取预先指定的新布局。

本机登录的 Codex CLI 已基于同一 seed 1950 的任务观测、十种通用原子技能接口和执行前求解的合法端口选项，生成 24 条按角色组合的完整候选；模型调用约 166 秒。输出经严格 JSON 契约、完整 PlanIR 和价值输入图校验，24 个图哈希在数字孪生执行前冻结。24/24 条完整物理试次与图哈希审计有效，但最终成功 **0/24**；失败包括清洁 9、滑块插入 4、插销接合 3、挡板压靠 6、接近 1、受力下降 1，见 `llm_24_generation_summary.json` 与 `llm_24_audit_summary.json`。这证明 LLM 候选生成流程可执行，**不证明 LLM 已找到完整正例**；不能把它与程序化组合池混称为同一种候选生成方式。

局部覆盖诊断显示，20 个随机挡板布局的 12 条候选池均自然混合成功和失败；较宽的清洁力/时长端口在一个布局上产生 7/12 局部成功。旧控制下 seed 1950 的合法前序链在第二条成功右插销状态下得到 2/8 左插销局部成功，但把手 0/8。通用受力卸载与微步接触反馈改动后，同一开发布局把手 5/8，未见布局 seed 1952 把手 2/8；未见布局 seed 1951 把手仍为 0/8。它们只证明部分技能有可选解，**不增加整任务正例数**。尤其 1951 的环柱径向偏差达数毫米，仍需改进观测与估计；不能为得到混合池而放宽验收。

后续控制器诊断把插销搜索螺距缩到由 CAD 净间隙确定的范围；一条事后拼接的开发诊断计划因此通过两侧插销，并在支撑后静置再开爪时通过把手放置。然而后续整任务验收中，右插销在把手操作后偏移约 0.14 mm，零穿透连续接合失败。此计划使用了局部阶段结果构造，**仅用于定位控制瓶颈，不进入自然候选池或价值训练**。

另查出最终功能行程的二次抓取原先固定使用 3 N，未使用计划中把手抓持力端口。本地代码已将此端口接入行程控制与价值输入图；该变更会形成**新运行时**，必须重新采集所有布局，不能与上述 `aa375b3d…` 结果混合训练。
