# V8 参考执行策略：重放、控制修复和九次完整运行

本报告是开发诊断，不是价值模型成绩。代码从 `220e6c4` 延续到 V8 分支；没有修改实体结构、孔径、V8 插销验收、任务行程或隐藏绑定。`reference_matrix_mj237_np126/` 保留九次原始 `result.json`、`steps.json`、场景和输入，`nine_runs.csv` 是索引。

## 1. V7 成功候选的精确重放

历史 `result.json` 保存了 seed 1200、L1、场景配置、夹持力 8 N、插入速度 0.006 m/s、扰动和候选 ID，却没有直接保存完整 PlanIR。`replay_v7_reference_v8.py` 按历史脚本重建计划，逐项核对场景配置与候选 ID `08fafc1b0668beb1f7c5`，并在执行前保存 `replay/reconstructed_plan.json`。这一严格核对在原 Windows 环境成功；服务器因初态浮点指纹不同，不能声称同 ID 精确重放。

Windows MuJoCo 2.3.7 的 V8 重放：旧轨迹共 158 步、完整成功；新轨迹前 112 步的技能次序和通过状态相同，首次状态分歧在第 112 步 `inspect_pin_inserted(pin_right)`。V7 验收通过，V8 验收失败；右销有效深度仍约 7.83 mm，但满足原方孔实体净空的轴段不足 6 mm。V8 保持失败判定。`replay/steps.json` 和 `replay/replay_result.json` 保留详细轨迹。仅改用仿真真值挡块/滑块位姿的 `ideal_only` 配对也失败，且更早在左销失败；理想位姿没有计入视觉成绩。

## 2. seed 1201 故障定位与同案修复

`failure_trace_1201.csv` 从原始 12 候选 `steps.log` 提取终止原子技能、零件、命令和指标。具体根因包括：

- `wipe_tool/press_seat`：守卫下降在接触力到达停止值时终止；随后压装控制直接因该力值退出，实际未再下压，原高度误差 1.86 mm。增加最多 1 mm、受力上限 8 N 的闭环微量下压，原 1.5 mm 控制带保持不变。同一 seed 1201 名义案例从第 18 步失败推进到左销抓取阶段。
- `pin_left/select_grasp`：单一 IK 初值报告无可用抓取；同一观测抓取点采用固定多初值可找到经碰撞检查通过的解。新增有预算的确定性多初值搜索与实际路径检查；同案继续推进至左销抬升。
- `pin_left/lift`：线性 IK 在靠近托架处失效。已尝试多初值关节路径，每条均作携物碰撞检查；无有效路径时明确失败，不忽略销轴与托架约 2 mm 的碰撞。
- 两条 `pin_left/plan_transfer` 失败轨迹的检查证据为机械臂自身碰撞；其余候选还包含右销插入抓取丢失及孔道净空失败。增加搜索并不等于已经验证这些候选可执行。

1202 同案中，`align_axis(handle)` 原以 1.22 mm 残差失败；增加闭环迭代后通过该控制步骤，最终独立 `inspect_seat` 仍以 2.38 mm 位姿误差失败。验收容差未变。具体结果见 `replay/1202_after_align.json`。

## 3. 九次独立 Session 完整运行

同一参考策略使用历史成功方案的技能顺序与参数骨架（销夹持目标 8 N、插入速度 0.006 m/s），执行期根据 RGB-D 重新定位挡块和滑块并更新插销目标。每次运行重新创建场景与 Session。三个 L1 开发布局预定为 1200、1202、1203，各运行三次；均为名义扰动，重复是执行一致性检查，不是扰动鲁棒性估计。服务器环境为 MuJoCo 2.3.7、NumPy 1.26.4、OpenCV 4.11.0、EGL。

| 布局 | 重复 | 清洁通过 | 首个完整任务失败 | 完整成功 |
|---|---:|---:|---|---:|
| 1200 | 3/3 | 3/3 | 左销 `slide_insert` 抓取丢失 | 0/3 |
| 1202 | 3/3 | 3/3 | 左销 `slide_insert` 抓取丢失 | 0/3 |
| 1203 | 3/3 | 3/3 | 左销 `lift` 找不到无碰撞路径 | 0/3 |

提高声明夹持力 8→12 N 的同案测试未改变实际双侧接触力（均约 8.00 N），且在同一插入位置失败；这是该参数在当前夹爪位置/控制范围已饱和的直接证据。把销抓取高度从 +1 mm 改到 -2 mm 改变了运动/姿态，但仍在左销插入丢失抓取。不能据此宣称“更大力”或“更慢”能解决问题。

## 4. 环境异常和证据边界

先前服务器环境 MuJoCo 3.13.0 的九次开发运行保存在 `reference_matrix/`，与本报告主矩阵分开。首次搭建 MuJoCo 2.3.7 远端环境时，NumPy 2.2.6 使接触法向和位置字段出现全零/重复坐标，九次运行均误报无支撑；`invalid_numpy2/summary.json` 保留记录，但这些是环境异常，不计作物理失败。切换到 NumPy 1.26.4 后，桌面接触法向恢复为竖直，支撑力可测，清洁阶段通过。

**结论：尚未建立一套符合 V8 标准且可重复完整成功的参考策略。** 局部技能与阶段推进已实测，但九次完整任务均失败。当前不具备以这套策略生成有效候选并开展公平价值筛选对比的条件。下一步的明确瓶颈是销的稳定持有/插入及托架脱离路径，然后是 V8 原方孔净空与把手最终位姿；在这三处形成完整成功并用多布局重复验证之前，不应训练或比较价值模块。
