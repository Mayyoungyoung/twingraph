# V19：随机场景下的单阶段自然覆盖、图价值训练与精验对比

## 实验边界

本轮把局部物理成功和完整滑台装配成功严格分开。挡板标签只表示从同一个真实滑块检查点出发，挡板被释放并在底座安装区域内稳定支撑；它不表示孔位对准、插销接合、往复行程或最终功能验收。滑块、两侧销钉和把手的阶段审计分别要求前序阶段真实执行成功，不移动或预置零件。

候选来自已有 V12 场景观测/CAD/技能目录生成器的前 `N` 条构造顺序方案。顺序在结果出现前固定；抓取、路径和接触参数来自技能允许范围。失败仍是物理负例，运行时指纹变化、超时和编译错误为无效记录。测试池没有按标签挑出“容易”的候选。当前批量矩阵不是逐场景在线大模型生成；V18 有独立的 Codex 原子计划生成与执行冒烟证据，批量训练/比较不把程序化候选冒充在线 LLM。

## 单阶段覆盖协议

- `scripts/audit_natural_stage_coverage.py`：先用正常物理技能取得合法前序检查点；随后重新观测、重新生成目标阶段候选，从同一检查点逐条验证。当前审计按场景的首个预结果成功前序继续，不把前序失败计作后续负样本。
- `scripts/collect_end_stop_natural_pool.py`：固定 48 条生成池，提交前 12 条；挡板局部稳定支撑在同一个滑块检查点独立验证。
- `scripts/collect_cleaning_natural_pool.py`：从 fresh scene 执行正常清洁控制器的局部范围，记录天然覆盖；清洁尚未纳入 V15 原子图价值训练，因为现有图编码没有清洁原子调用及擦拭端口。
- 每个布局的 `request.json`、各候选的 `input_graph.json`/`result.json` 和 `summary.json` 保留方案、观测、图哈希、物理标签、运行时哈希及耗时。出现无效试次的布局整体排除并在新的目录完整重跑，不拼接不同前序检查点。

## 价值训练与比较协议

`scripts/train_and_compare_stage_value.py` 从执行前的完整原子技能图输入 V15 通用图网络。训练代码不用候选编号、seed、结果或阶段专用特征；候选图哈希必须与物理结果记录一致。只将 12 条完整有效且自然包含成功与失败的布局用于排序训练。所有尝试的布局及全正、全负、不完整情况均写入 `coverage_audit.json`。

布局在读标签前由 seed 模 5 分配：余数 0 为测试、1 为验证，其余为训练。模型和训练轮次只依据验证集选择，测试集只在选择后评估。随机 Top-4 的命中概率、期望验证次数和期望时间用组合概率精确计算；价值 Top-4 按分数顺序精验，成功后停止；全孪生基线完整验证 12 条。三个方法使用同一批物理结果。报告时间为每条候选实测墙钟的串行求和，价值方法另计图编码和模型打分。并行采集的实际历时、共同候选生成/检查点耗时均不混入这个数。

测试阶段还报告按布局重采样的配对差值区间。它描述本批随机布局的不确定性，不替代更多独立布局或真实部署计时。

## 当前限制

原子技能本身保持通用接口，但 V12 任务编排包含滑台 CAD/装配先后条件。覆盖审计尚不能证明每个随机布局的每一阶段都存在成功方案；对全负池会如实报告。尤其最终行程与保持检查必须在两销和把手完成后进行，不能由挡板稳定放置的正例推断。清洁控制器目前仍通过任务宏调用通用原子技能，V15 编码只覆盖装配图，不能给它一个可信的同结构价值排序结果。
