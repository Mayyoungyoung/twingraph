# TwinGraph v6 价值模块总结

## 1. 模块目的与接口

价值模块在真正执行动作前，估计每个候选任务计划完成“五零件滑台装配”的成功概率，用于把 12 个候选计划缩减为需要数字孪生验证的 Top-4。

输入分为两部分：

1. 结构化输入：当前机器人状态、五个零件的检测位姿、任务目标，以及候选 `PlanIR` 程序。程序由带类型/单位/坐标系/已知或延迟状态的技能调用组成，并先编译为可执行技能图。
2. 决策边界前的视觉输入（可选）：固定的全局斜视 `task_view` 和固定俯视 `top_view`，每个视角为 80×80 的 RGB-D；RGB 是 `uint8`，深度是毫米 `uint16`。不加入需要额外主动运动才能获得的腕部近景。

输出是每个候选的连续价值分数 `p∈[0,1]`、原始 logit、稳定排序、Top-4 候选 ID、输入诊断和技能图哈希。系统层再输出 Top-4 的数字孪生验证结果、经验成功率、最终 `selected_candidate_id` 和独立目标执行结果。

本轮在线决策没有调用外部大模型：任务计划由冻结的候选生成器/规划器记录产生，价值模块只负责对这 12 个已绑定、可执行的候选程序打分和筛选。

## 2. 当前模型

结构化程序由固定 `InputSchema` 编码；候选 ID、历史 rollout 输出和执行成本不作为特征。程序分支是 MLP，视觉分支是 RGB-D CNN，之后融合 `program`、`vision` 和逐元素乘积 `program×vision`，输出一个成功率 logit。训练目标是三次成对扰动执行得到的经验完整成功率。

训练了四种视角模式 `none/task/top/both`，每种模式使用 17、29、43 三个随机种子，共 12 个模型。模型和视角只按验证集配置均值 Brier 选择，不用测试集调参；最终选中 `both_43`：

- 视角：`task_view + top_view`；
- 验证 Brier：0.1171830914；
- 冻结硬判定阈值：0.7206604504（按验证集硬预测 Brier 选出）；
- 阈值只用于报告/二值判定，候选排序使用原始连续分数/Logit。

## 3. 数据收集

每个场景配置独立随机化零件供应位姿和感知条件：零件平面位移 ±12 mm、偏航 ±7°、光照 0.78–1.22、颜色 0.86–1.14、相机平面抖动 ±6 mm。正式数据按配置划分为 train 64、val 16、test 16；每个配置生成 12 个候选计划，每个候选进行 3 次共享扰动的完整物理执行，因此共有 96×12×3 = 3456 条完整试验记录。

重复执行还随机化摩擦 ±8%、执行器增益 ±1.5%、质量 ±4%、阻尼 ±6%，并使用 0.25–1.25 mm 的检测位置噪声；名义重复也保留 0.35 mm 感知散布。候选之间共享同一重复扰动，保证配对比较；每次执行都在独立 MuJoCo 会话中完成，记录输入/技能图/试验哈希、状态轨迹和终态。最终审计为 96 个完成配置、3456 次执行、0 个未分类失败。

## 4. Top-4 到实际执行的规则

1. 价值模型一次性给 12 个候选打分并按 logit 降序排列。
2. 只取前 4 个候选做数字孪生验证；每个候选 3 次，使用相同的 twin 扰动。
3. 对每个候选计算 `成功次数/3`。选择规则是成功率降序，完全相同则按候选池原始顺序；候选必须至少有一次有效、非超时成功，且成功率 ≥ 0.5。
4. 若没有候选满足规则则 abstain；否则把选中的计划从目标场景快照重新绑定，并在 3 个新建、独立的 target 会话上实际执行。不会复用 twin 结果或缓存执行结果。

在下面的视频案例（seed 71400）中，模型排序为：

| 模型排名 | 候选 ID | 分数 |
|---:|---|---:|
| 1 | `e29adb7ac28b5567e9ec` | 0.9756 |
| 2 | `e83f0990783267c02a3b` | 0.8813 |
| 3 | `b2df063756dbea03a712` | 0.5722 |
| 4 | `57ed526f426891e1124a` | 0.3036 |

四个候选的 twin 验证结果均为 3/3 成功。由于四者成功率相同，按候选池原始顺序打破平局，最终实际执行的是 **`57ed526f426891e1124a`**；它的 3 次独立 target 执行均成功。这个选择不是“分数最高者直接执行”，而是“价值排序缩小验证范围，再由 twin 经验成功率作最终选择”。
