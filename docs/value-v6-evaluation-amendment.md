# v6 评估更正记录

正式采集与模型源码保持冻结；本记录只涉及采集完成后的评估脚本。

## 发现

初版 `scripts/evaluate_value_v6.py` 用验证集平衡准确率（再以普通准确率和接近 0.5 的程度打破平局）选择分类阈值。这与本轮要求“只按验证集 Brier 选模型和阈值”不一致。该逻辑不参与采集、候选程序编译、物理执行或模型训练，因此没有改变已采集数据和 checkpoint 接口。

## 更正

阈值现在枚举验证集模型概率，并最小化硬 0/1 预测相对于同一经验成功率目标的平方误差（hard-forecast Brier）；仅以距离 0.5 和较低阈值作确定性平局处理。模型仍按配置均值验证 Brier 选择，测试集完全不参与模型或阈值选择。远程评估结果在更正脚本同步后重新生成。

正式采集期间出现的 3 个 240 秒物理截尾组已保留在远程 `results/v6/formal/censored/`；同种子恢复运行使用 600 秒上限，生成的 96 组最终数据仍逐组通过 source/input/graph/paired-trial 审计，累计 3456 条完整物理执行记录。

系统批处理的第一次尝试还暴露了一个仅在 v6 部署适配层出现的完整性问题：`ValueScorer` 返回了图哈希但没有返回 `system_v5` 完整性检查所需的序列化 graph。第一次尝试的错误输出已保留；`run_value_v6_system_batch.py` 现在在适配层用同一观测和候选计划重建并附加 graph，未改变 `simbench/value` 中的冻结源码、评分数值或物理执行接口。
