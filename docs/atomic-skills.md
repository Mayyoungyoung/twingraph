# 11 个原子技能

这里的原子技能是一个可独立调用、职责明确的动作或信息处理单元。统一接口接受参数并返回结果；其中一些改变物理状态，另一些只输出信息。不会把运动方向、抓法编号、路径算法或控制策略另算作技能。

| 技能 | 输入 | 输出 / 成功条件 |
|---|---|---|
| **检测 detect** | 场景观测 | 对象列表及观测数据；当前是带噪声的仿真位姿观测 |
| **物体位姿估计 estimate_pose** | 对象观测 | 物体位置、朝向与不确定性 |
| **抓取位姿估计 estimate_grasp** | 物体位姿、几何 | 多个夹爪抓取位姿、开度、接近姿态 |
| **路径规划 plan_path** | 当前状态、目标、几何/接触约束 | 多条运动候选，或供插入/恢复执行的参数；不推进仿真 |
| **移动 move** | 目标、相对位移或已有路径；持物对象、约束参数 | 到达目标，满足对应跟踪、碰撞及保持抓持要求 |
| **抓取 grasp** | 对象、夹持力；夹爪已移动到抓取位姿 | 建立对同一对象的双侧抓持 |
| **放置 place** | 持物对象、已有支撑位置、容差 | 释放前确认支撑，释放后对象仍在目标范围内 |
| **插入 insert** | 对象、插入参数、执行策略 | 按配合几何推进；返回位置、深度、接触等结果，保留原策略的安全/成功检查 |
| **压靠 press** | 对象、目标高度、力阈值 | 接触力和压靠高度同时满足要求 |
| **测量 measure** | 测量量名、对象 | 位置、接触力、行程或间隙数值及单位，不包含任务验收结论 |
| **检查 inspect** | 位姿目标、测量数据、阈值或验收要求 | 合格/不合格与残差 |

代码中 `move` 表示移动，`place` 专指放置。搬运、上移、下移、回位、退出、转腕及沿导轨移动均落在同一个移动节点。夹爪张开准备、选择第几个抓法等是内部步骤或候选绑定操作，不另列节点。

## 职责边界

物体位姿估计回答“物体在哪里、朝向怎样”；抓取位姿估计回答“夹爪如何接近和夹住它”，两者输出不同。路径规划产生执行参数，移动才推进物理状态。同一规划方法的多条路线仍是同一个技能的不同参数实例。

抓取不自动包含搬运和抬升。放置不自动从远处搬运过来；先用移动到达支撑位置，必要时用带接触保护的移动和压靠完成就位，再调用放置。这个边界让同一套技能能组合到装配、取放和工件操作中。

插入关心配合约束下的运动，压靠关心指定位置处的接触力和落座。测量可以正确返回负间隙；检查再根据要求判定该值不合格。它们不应混成“测到不合格就代表传感器测量失败”。

## 调用示例

```python
s.call("detect")
s.call("estimate_pose", part="cube")
s.call("estimate_grasp", part="cube")  # 输出多个抓法，交给候选构造器选择/绑定

# 这里假设候选构造器已绑定 grasp，并生成 transfer 路径。
s.call("move", path="transfer")
s.call("move", part="cube", grasp="grasp")
s.call("grasp", part="cube", force=3.)
s.call("move", part="cube", delta=[0, 0, .10])   # 上移
s.call("move", part="cube", delta=[0, 0, -.03])  # 下移，同一个技能

# 先通过移动把物体带到支撑目标；此处 target 是物体目标位置。
s.call("place", part="cube", target=target)
s.call("move", delta=[0, 0, .10])                # 空爪退出，同一个技能
s.call("move", target="home")                  # 关节回位，同一个技能

s.call("measure", quantity="clearance", part="carriage", as_="gap")
s.call("inspect", what="measurement", artifact="gap", minimum=0.)
```

绝对目标 `move(target=xyz)` 默认指定末端位置；`reference="object"` 指定持物对象位置，并沿用原来的精对准检查。三维相对移动接受 `delta`。旧 `move(mode="lift")` 等写法仍兼容，但无需在任务层再维护这些名字。

`plan_path(method="joint")` 产生关节搬运候选，`method="cartesian"` 产生直线轨迹，`method="contact"` 生成插入目标/速度/力限。它们共用一个路径规划节点，内部求解器各自保留适用条件。默认多抓法、多搬运路径构造与跨抓法绑定检查沿用上轮实现。

`insert(strategy="axis"/"spiral"/"learned")` 复用已有执行器。螺旋搜索的成功只表示孔口进入，完整装配仍需后续推进与检查；学习策略仍是行为克隆。不同策略的成功语义和前置条件仍记录在各自契约中，不被名称合并抹掉。

## 图谱与已有实现

默认 `python -m simbench.assembly.graph` 只导出 11 个节点，内部条件分支放在节点契约内。验证器解析具体参数后，和执行器读取相同契约；不会要求移动同时满足“空爪”和“持物”两种互斥分支。

`--components` 才导出内部处理函数，用于调试和旧演示兼容。旧 30 项录像保留作回归材料，[默认录像索引](demos/INDEX.md) 按 11 个技能整理。

完整滑台流程使用检测、估计、规划、移动、抓取、插入、压靠、放置、测量和检查。现有基础能力适用于桌面刚体操作与当前装配，旋拧、柔性件等需要新增实际控制能力后才能扩展。
